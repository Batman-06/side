---------------------------------------------------------------------------
1. WHAT RUNS WITH vs WITHOUT AN API KEY
---------------------------------------------------------------------------
Every unit notebook is split into two kinds of cells:

  • "From scratch" cells  -> plain Python, NO API key, NO internet.
                             These always run. (This is ~half of every unit.)
  • "SOTA" cells          -> call the OpenAI API, so they need OPENAI_API_KEY
                             and will incur a small cost (pennies).

A few "SOTA" cells are PSEUDO-CODE only (they just print an explanation and
need no key / no network):
  - unit5 §6  sandboxing  (real-sandbox pattern, commented)
  - unit7 §5  benchmarks  (SWE-bench loading pattern, commented)
  - unit9 §1  fine-tuning (JSONL + fine_tuning.jobs pattern, commented)
  - unit9 §2  RLHF/DPO    (preference-dataset pattern, commented)

So with NO key you still get a complete, runnable course; the key only
"lights up" the live-model half.

    OPENAI_API_KEY   (required ONLY for SOTA cells)

Set it for the session:

Or persist it (zsh):
    echo 'export OPENAI_API_KEY="sk-..."' >> ~/.zshrc && source ~/.zshrc

Each unit's Setup cell prints whether the key is detected:
    ✅ key set — SOTA cells will run
    ⚠️  no OPENAI_API_KEY — from-scratch cells still run; SOTA cells need a key

No other env vars are needed. (The optional Batch/fine-tune/E2B patterns in
the pseudo cells would need their own keys, but those cells don't execute.)

6. HOW TO RUN — three ways
---------------------------------------------------------------------------
A) VS Code (you already have it open):
   - Open the .ipynb, click the kernel picker (top-right), choose "Python (test)".
   - Run All. from-scratch cells work immediately; SOTA cells need the key.

B) JupyterLab (browser):
       conda activate test
       export OPENAI_API_KEY="sk-..."
       jupyter lab
   - Open a unit, select the "Python (test)" kernel, Run All.

C) Headless (run a whole notebook from the terminal, saves outputs in place):
       conda activate test
       export OPENAI_API_KEY="sk-..."     # omit to run only from-scratch cells
       jupyter nbconvert --to notebook --execute --inplace unit1_reasoning_and_control.ipynb
   Run every notebook at once:
       for nb in unit*.ipynb; do \
         jupyter nbconvert --to notebook --execute --inplace "$nb"; done
   (Without a key, SOTA cells will raise — add  --allow-errors  to continue.)

8. THE MCP SERVER FILES
---------------------------------------------------------------------------
mcp_server.py — exposes 5 math tools (mcp 2.x MCPServer API). Notebook 04
  imports it in-process (`from mcp_server import mcp`), so the FILE must be
  present to run 04 — but you do NOT need to start it separately.
  Optionally, you can also run it as a real stdio MCP server (e.g. to wire it
  into Claude Desktop):
      conda activate test
      python mcp_server.py        # stdio MCP server; Ctrl-C to stop

mcp_server_raw.py — the no-library version (pure stdlib). Notebook 03 both
  imports it and launches it as a subprocess, so the FILE must be present to
  run 03. You don't invoke it by hand.

Again: units 1-9 need neither file.

---------------------------------------------------------------------------
9. TROUBLESHOOTING
---------------------------------------------------------------------------
- "No module named openai/mcp"  -> wrong kernel. Confirm the notebook kernel
  is "Python (test)", and that you pip-installed into the active "test" env
  (run:  python -c "import sys; print(sys.executable)"  — must be .../envs/test/).
- "No module named 'mcp.server.fastmcp'" -> you're on mcp 2.x (expected).
  The code uses mcp.server.mcpserver.MCPServer. Don't downgrade.
- 401 / AuthenticationError -> OPENAI_API_KEY missing or invalid for SOTA cells.
- RateLimit/quota errors on SOTA cells -> billing/quota on the OpenAI account.
- Want zero cost -> just don't set the key; run only the from-scratch cells.
